## 方向（ユーザーの決定）
見た目は **iPhone の写真アプリ**（いまの「編集」＝`Trimmer` と同じ作り）、操作は **DaVinci Resolve の Cut ページ**に、できるだけ近づける。第 1 版の案 A〜D（切り出して集める／タイムライン／見ながら押す／自動分割）は、採用しないと決まったので、コードから外した（git の履歴には残る。比較の数字は、下の表）。

## 見かた（試作の起動）

```bash
pnpm exec vite --config proto/vite.config.ts   # http://localhost:5181/
```

- 同じ Wi-Fi の iPhone からは `http://<このMacのIP>:5181/`（スマホ幅で開くと、画面いっぱいになる）。
- 案は 1 つ（ProtoR）。細部だけ、`?split=under|selected`（分割・頭を切る・尻を切るが効く区間：再生ヘッドの下／タップで選んだ区間）、`?delete=ripple|gap`（削除：消えて詰まる／斜線で残る）、`&confirm=sheet|undo`（キャンセル：下からのシート／出さずにトースト）で切り替える（画面の上のボタンでも切り替えられる）。
- 「動画を選ぶ」で、手元の動画を読み込める。何も選ばないと、サンプル（`sample.mp4`、24 秒：①抽出 0–5／②スチーム 5–11／③注ぎ 11–20／④できあがり 20–24。**合成の動画で、本物のカップの動画ではない**）。
- 画面の右（スマホ幅では下）に、「操作の回数」（指を置いた回数）と、できあがりの区間が出る。書き出し（ネイティブ）は動かさない（モック）。
- **共通のシナリオ**：サンプル（24 秒）で、(1) 頭の 2 秒を切る (2) ②スチーム（5–11 秒）を抜く (3) 尻の 4 秒（④）を切る (4) 完了。できあがりは「2–5 → 11–20」（12 秒）になれば正解。BGM・元の音は、試作では扱わない（今の部品のまま）。

## 1. 何を求められているか

### 利用者と場面
ラテアートの練習で、1 回の撮影に「抽出 → スチーム → 注ぎ（ラテアート）」が入る。撮り直しは面倒（ミルクが無駄になる）。撮ったあと、YouTube に出す動画を素早く整えたい。**記録の手間をほぼゼロに**（理念）。動画は 5〜60 秒程度、縦、iPhone のみ。

### したいこと（作業）と、頻度・重要度（推測。実機の観察と作者の使い方から）
| 作業 | 頻度 | 重要度 | 補足 |
|---|---|---|---|
| 不要な頭と尻を切る | 毎回 | 高 | 撮り始め・撮り終わりの手の動き。いちばん多い |
| 途中の不要な場面を抜く | よく | 高 | 「抽出・スチーム・注ぎ」を 1 本で撮り、要る場面だけ残す（作者の本当の目的） |
| 確認して書き出す | 毎回 | 高 | 全体を再生して確かめ、完了 |
| 元の音を消す | ときどき | 中 | スチームの音と BGM がぶつかる |
| BGM を付ける | ときどき | 中 | 同梱の曲が無いと使えない |
| 複数の動画をつなぐ | たまに | 中 | 1 本で撮れば要らない。撮り足したとき |
| 場面を並べ替える | まれ | 低 | 順に撮るので、ほぼ要らない |

→ **「頭と尻を切る」「途中を抜く」を、最少の操作でできる**のが核。並べ替え・複数動画のつなぎは、あとでよい。

### 制約
- スマホ縦画面・片手の親指・指の太さ（取っ手 44pt 以上）・画面が狭い。iOS のみ（Android・Web 本番には出さない）。
- Plus（無料 3 回。つなぐ・分割・BGM は 1 回）の数え方は、変えない。切り取りだけは、いつでも無料。
- 理念：説明文を並べない／ボタンは静かに／押し付けない／がたつきを残さない／迷ったら、足すより削る。

### 今の画面（#162・#163）の使いづらさ（実機の FB を、操作の言葉で）
実機の指摘と、シミュレーターでの確認から。**推測は「推測」と書く。**
1. **取っ手が小さい・つかみにくい**（実機の FB）。黄色の取っ手の幅は細く、両端に 2 つ。短い区間では、2 つが重なる（推測：親指の面積が取っ手より大きい）。
2. **分割・取っ手・外すの関係が分かりにくい**（FB）。区間の取っ手が、隣の境目を動かす作りは、仕組みとして正しいが、「なぜ隣が動くか」は画面から読めない。
3. **「選んでから操作」が多い**（事実）。チップを押す → 取っ手/分割/外す。白い線を置く位置と、選んだ区間が別のもの。
4. **結果が見えにくい**。外した区間は、フィルムの斜線に出るが、チップから消える。全体を見るには再生するしかない。
5. **確認の見た目が、アプリの他と揃わない**（FB）。黒い全画面に、明るい枠。#162 で直したが、画面全体の配色（黒）が、アプリの世界観（窓辺のカフェ）から浮いている（推測）。
6. 手順の多さ（事実）：シナリオ（頭 2 秒を切る＋②を抜く）は、いまの画面で、**およそ 9〜10 回の操作**（白い線を置く×3、分割×2、チップ選び×2、外す×2、完了。シミュレーターで確認した操作から数えた）。

## 2. DaVinci Resolve（iPad 版・Cut ページ）の操作：確認できたことと、確かめきれなかったこと

**先に結論**：Resolve for iPad の**タッチ操作（ジェスチャー）の公式の説明は、取れなかった**（App Store の説明・Blackmagic のページ・第三者の解説を当たったが、どれもタッチの動きは書いていない）。下の「確認できた」は、設計（Cut ページの作り）についての記述だけ。タッチの動きは、デスクトップ版の考え方と私の知識から作った（【推測】）。実機（iPad）で、ユーザーの目で確かめてもらえると、一番確実。iPhone 版が出ているかも、確認できなかった。

### 確認できたこと（出典は末尾）
- Cut ページは「速く覚えられて、速さのために作られた」画面とされる（App Store の説明）。
- **2 段のタイムライン**：上は**プロジェクト全体**（拡大せず、ナビゲーションと並べ替え用）。下は**トリム用のタイムライン**で、「**いまの再生ヘッドの位置の拡大**」を常に出す（Larry Jordan）。移動は、上の段で再生ヘッドを動かす。
- **トリム**：ripple・roll・slip・slide。下の段で、区間の端をつかんでドラッグする（Larry Jordan）。「safe edit」は、隣の区間を上書きしないトリム（App Store の説明）。
- **再生ヘッドに対するトリム**：Cut ページの左の「Trim」に、「**Trim Start to Playhead**」「**Trim End to Playhead**」がある（ripple。間が詰まる）。**マグネティック・タイムライン**を入れておくと、ripple で隙間が残らない（exlima）。
- 分割は、再生ヘッドの位置で区間を分ける（編集点を足すだけで、コマは消えない）（デスクトップ版の解説）。
- ripple 編集は、隙間を自動で詰める（第三者の解説）。

### 確かめきれなかったこと（私の想定のまま）
- 再生ヘッドを**直接つかんで動かす**／タイムラインを**なぞると**動く、スナップ（境目に吸い付く）の細部。
- 区間を**タップして選び**、黄色い枠が付く動き（Resolve は、選ぶと明るくなる）。
- Ripple Delete のボタンの位置・Undo／Redo のボタンの場所（デスクトップでは、ショートカット）。
- ピンチでのズーム（iPad 版で、2 本指のピンチが効くか。ズームの資料は、見つからなかった）。

### 試作に取り入れたもの（Resolve から）と、写真アプリから
| 取り入れた点 | 元 | 確かさ | 理由（何が速く・間違いにくくなるか） |
|---|---|---|---|
| **2 段のタイムライン**（上：全体、下：再生ヘッドの周りの拡大） | Resolve Cut ページ | 確認 | 全体で場所を決め、拡大で正確に合わせる。1 本のタイムラインだと、「全体が見える」と「取っ手が太い」が両立しない |
| **頭を切る・尻を切る**（Trim Start/End to Playhead） | Resolve | 確認 | 一番多い作業（頭と尻）が「再生ヘッドを置く → 1 回押す」で終わる。**分割して選んで削除、の 3 手が 1 手になる** |
| **再生ヘッドは、どちらの段でも見える**。境目に吸い付く | Resolve（スナップ） | 推測 | 境目ぴったりに置ける。指の細かい位置合わせを減らす |
| **区間の端のトリム**。隣が残す区間なら、境目が一緒に動く（roll）。隣が外した区間なら、それが伸び縮みする（ripple） | Resolve のトリム | 確認（種類のみ） | 重ならない・隙間ができない（#163 の「境目を 1 つの値で持つ」を、そのまま使う） |
| **削除は、消えて間が詰まる**（ripple）。斜線で残す版も用意 | Resolve（Ripple Delete） | 確認（詰まること） | 「外した」ことが、見て分かる（消える）。結果の長さと画面が一致する |
| **取り消し・やり直しが、操作の列にある** | Resolve／各アプリ | 推測 | 間違いを、確認なしで戻せる。確認（シート）を出す回数が減る |
| 黒い全画面・フィルム・黄色の枠と取っ手・上の「キャンセル／完了」 | **写真アプリ**（いまの `Trimmer` と同じ部品・クラスを、そのまま使う） | 確認 | 利用者が慣れている見た目。新しい部品を増やさない |
| **キャンセルは、変更があれば、下からのシート**（「変更を破棄」「続ける」） | 写真アプリ | 確認（写真アプリの「変更を破棄」） | アプリの中で浮かない。iOS の標準の作り |

### 意図して変えたところ（写真アプリ・Resolve との違い）と、理由
- **取っ手は 44pt**：写真アプリの黄色い取っ手（14pt。反応は 38pt）を、拡大の段では 18pt（反応は 44pt）に。親指で、つかみやすく（実機の FB「取っ手が小さい」）。
- **分割・頭を切る・尻を切るは、再生ヘッドの下の区間に効く**（選ばなくてよい）。Resolve は「選んだ区間（なければ、再生ヘッドの下）」。細部は `?split=selected` で、「タップで選ぶ」版と比べられる（選ぶ手が増えるが、意図しない区間に効かない）。
- **ボタンの文字**：アイコンの下に、2〜4 文字（アプリは、他の画面でも「分割」「外す」と文字を使う）。説明文は足さない。Resolve は、アイコンだけ。
- **自動の分割は入れない**（ユーザーの決定）。BGM・元の音の操作は、この画面の外側の部品（変えない）。

## 3. 操作の回数（共通のシナリオ。指を置いた回数。「完了」を含む）

| 画面 | 頭 2 秒を切る | ②を抜く | 尻を切る | 全体（完了込み） | 備考 |
|---|---|---|---|---|---|
| **現在（#163）** | 3〜4 | 5〜6 | 3〜4 | **約 11〜13** | 区間を選んで、取っ手・分割・外す |
| 第 1 版 A 切り出して集める | 3 | 3 | （②のあとを、そのまま使えば 0） | 6（尻なしの場合） | 取っ手 44pt。端に近い |
| 第 1 版 B タイムライン | 3 | 5 | 3 | 約 12 | 「選んでから」が無い |
| 第 1 版 C 見ながら押す | 1 | 1 | 1 | 3〜4（実時間がかかる） | 精度が出ない |
| 第 1 版 D 自動分割 | 不可 | 1 | 1 | 3（頭の 2 秒が不可） | 場面が分かれたとき |
| **今回（Resolve×写真）ボタンだけ** | 2（なぞる・頭を切る） | 4（なぞる・分割・なぞる・頭を切る） | 2（なぞる・尻を切る） | **9**（Web 版で、この手順で動かして、できあがり 2–5 → 11–20 になることを確認） | |
| **今回：端の取っ手を引く** | 1（始めの取っ手を 2 秒へ） | 4 | 1（終わりの取っ手を 20 秒へ） | **7** | 取っ手の操作は、疑似的に動かして確認（指ではない） |

読み方：シナリオは、「頭・途中・尻」の 3 つで、最も手数が多い（途中を抜く）。頭と尻だけなら、**「なぞる → 頭を切る」「なぞる → 尻を切る」の 4 手（完了込みで 5 手、取っ手なら 3 手）**で終わる。途中を抜くのは、「分割 → 頭を切る」の組み合わせが、「分割を 2 回 → 選んで削除」より、1 手少ない。

## 4. 試作の限界（正直に）
- **指でのドラッグ**は、マウスと、疑似的な pointer イベントでしか確かめていない。指の太さ・端の近く・2 本指のピンチは、実機（iPhone）で確かめてもらう必要がある。
- ripple（詰める）で**左の取っ手を引くとき、取っ手が指から離れて見える**ことがある（区間の頭が動かず、中身が動くため。Resolve の ripple トリムと同じ）。`?delete=gap`（斜線で残す）は、取っ手が、指に付いてくる。どちらを採るかは、触って決めたい。
- 拡大の段の絵は、0.5 秒単位に揃えた小さな絵（`SegFilm`）。初めて開くときは、絵が出そろうまで、数秒かかる（本番は、ネイティブで作る想定）。
- 書き出し・BGM・元の音・Plus の判定は、動かしていない。サンプルは合成の動画。
- 複数の動画のつなぎは、試作に含めていない（元の動画ごとに、同じ形を持つ想定。並べ替えは別の操作）。

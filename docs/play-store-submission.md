# Google Play への提出の準備

Android アプリ「ラテ帳」を、Google Play に出すための手順・判断・入力案をまとめたものです。
規約の確認日：2026-10-20。提出の前に、Play Console の画面と公式の案内を、もう一度確認してください（更新されることがあります）。

公式：

- [App testing requirements for new personal developer accounts](https://support.google.com/googleplay/android-developer/answer/14151465)（個人アカウントのテスト要件）
- [Understanding Google Play's app account deletion requirements](https://support.google.com/googleplay/android-developer/answer/13327111)（アカウント削除）
- [Provide information for Google Play's Data safety section](https://support.google.com/googleplay/android-developer/answer/10787469)（データセーフティ）
- [Target API level requirements for Google Play apps](https://support.google.com/googleplay/android-developer/answer/11926878)

App Store 側（iPhone）は [app-store-submission.md](app-store-submission.md)。ストアの説明文・カテゴリ・年齢区分の考え方は、そちらと同じにします。

## 1. 用語

- **applicationId**：アプリの「固有の名前」（`me.makimura.lattecho.app`。iPhone の Bundle ID と同じ。Google ログインから戻る URL スキームも同じ値）。Play に登録したあとは変えられない。
- **AAB**（Android App Bundle）：Google Play に上げる形式。端末ごとに、必要な部分だけが配られる。`.apk` は、端末に直接入れる確認用。
- **署名**：「この開発者が作り、途中で書き換えられていない」ことを、鍵で証明する仕組み。
  Google Play では、**Play App Signing**（Google が、配信用の鍵を預かる）を使う。開発者は、自分の**アップロード鍵**で署名して上げる。アップロード鍵をなくしたときは、Google に依頼して、作り直せる（配信用の鍵そのものをなくす事故が、起きない）。
- **versionCode / versionName**：`versionCode` は、Play が見る整数（**上げるたびに、前より大きく**）。`versionName` は、利用者に見える版（`1.0` など）。

## 2. 先に決めること

### 2-1. 開発者アカウントと、公開前のテスト（個人アカウントのとき）

- Play Console の開発者アカウントに登録する（登録料が、一度かかる）。**種類は、個人か組織か**を決める。
- **個人アカウントで、2023-11-13 より後に作ったもの**は、公開（本番）の前に、**非公開テストで、12人以上のテスターが、14日間続けて参加している**必要がある（そのあと、本番公開を申請する。審査は、通常7日以内）。途中で抜けたテスターは数えない。**組織アカウントは、対象外。**
  → 個人で出すなら、**テスター 12人の確保が、いちばん時間がかかる**。早めに、登録とテスターの募集を始める。
- 先に公開したい・テスターを集められないときは、組織アカウント（法人など）を使う手もある。

### 2-2. アカウント削除のルール（Play のポリシー）

Play は、**アカウントを作れるアプリ**に、次の2つを求める。

1. アプリの中で、アカウントとデータを削除できること
2. **アプリを持っていない人も、削除を依頼できる、ウェブのリンク**（Play Console の「データセーフティ」に書く）

ラテ帳の場合：

- Google でログインすると、サーバーにアカウントができる（同期用）。**ログインしなくても、すべての機能が使える。**
- 1 は満たしている：「設定 → アカウント → アカウントを削除」で、サーバーのデータをすぐに全部消せる。
- 2 は、**決める必要がある**。いまのプライバシーポリシー（`https://latte.makimura.me/privacy`）の「4. 保存期間・ログアウト・連携の解除・データの削除」に、削除の方法が書いてある。ただ、問い合わせ先は **GitHub の Issues（公開）** だけで、**アプリを消した人が、自分の情報を公開せずに依頼する窓口が無い**。

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. いまのポリシーのページを、そのまま出す（推奨） | 削除用 URL に `https://latte.makimura.me/privacy` を書く | 作り込みなしで、すぐ出せる | 審査で、「依頼の窓口が無い」と指摘されるかもしれない（数日、遅れる）。公開の Issues で依頼するのは、情報を公開することになる |
| B. 削除の依頼ページを作る | サイトに、削除の方法と、依頼の窓口（アプリの「ご意見・ご要望」と同じ仕組みなど）を持つページを足す | 指摘を避けられる | サイトの作業が増える（サーバーの変更を含む。**審査中はサーバー変更をマージしない**方針に注意） |

→ **A で出し、指摘されたら B を作る**のがおすすめ。急いで確実にしたいなら B を先に。
どちらにしても、**ポリシーの見出し「4.」に、直接飛べる URL**（見出しに `id` を付ける）があると、審査員に伝わりやすい。

### 2-3. 対象の API レベル

2026-08-31 以降、新しいアプリと更新は、**API 36 以上**を対象にする必要がある。ラテ帳は `targetSdk = 36`（`android/variables.gradle`）で、満たしている。更新するたびに、最新の要件を確認する。

### 2-4. Google ログインと YouTube の連携（Android 版）

- Google の審査（YouTube）は、2026-10-17 に通過済み（[oauth-verification.md](oauth-verification.md)）。
- iPhone と同じ、**ウェブアプリケーション**の OAuth クライアントを使い、ログイン・連携は、アプリの中のブラウザ（Android では Chrome Custom Tabs）で認可して、`me.makimura.lattecho.app://` で戻る。Android の実機で、**ログイン → YouTube 連携 → アップロード**が通るかを、必ず確かめる（エミュレーターは、Google のアカウントの入力が要る）。

## 4. アップロード鍵とビルド

### 4-1. アップロード鍵を作る（一度だけ）

**リポジトリの外で**作る（ホームなど）。鍵とパスワードは、公開リポジトリに入れない（`.gitignore` で、`*.jks`・`*.keystore`・`keystore.properties` は除外してあるが、置き場所は、はじめから外にする）。

```bash
keytool -genkeypair -v -keystore ~/lattecho-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

- 聞かれたパスワードは、**パスワードマネージャに保存する**。鍵ファイルは、**別の場所（クラウドの非公開の場所など）にも、バックアップを置く**。
- なくしたら：Play Console の「アプリの署名」から、Google に、アップロード鍵のリセットを依頼できる。

### 4-2. 署名の情報を、ビルドに渡す

`android/keystore.properties`（git に入れない）を作る。

```properties
storeFile=/Users/<あなた>/lattecho-upload.jks
storePassword=<パスワード>
keyAlias=upload
keyPassword=<パスワード>
```

`storeFile` は、絶対パスか、`android/` からの相対パス。同じ項目は、環境変数（`LATTECHO_STORE_FILE`・`LATTECHO_STORE_PASSWORD`・`LATTECHO_KEY_ALIAS`・`LATTECHO_KEY_PASSWORD`）でも渡せる。

### 4-3. AAB を作る

JDK 21 が要る。

```bash
pnpm app:build   # 画面を作って android/ へ入れる（VITE_API_URL をローカルの値にしたまま作らない）
cd android && ./gradlew bundleRelease -PrequireSigning -PversionCode=1 -PversionName=1.0
```

- できる場所：`android/app/build/outputs/bundle/release/app-release.aab`
- **`-PrequireSigning`** を付ける。鍵が無いときに、止まる（付けないと、署名なしの AAB が黙ってできる）。
- **`versionCode` は、Play に上げるたびに +1**（初回は 1）。同じ値や小さい値は、拒否される。`versionName` は、利用者に見える版。
- できた AAB を、Play Console の「テスト → 非公開テスト」（本番のときは「本番環境」）に上げる。

## 5. ストア掲載情報（案）

説明文・カテゴリ・年齢区分の考え方は、[app-store-submission.md](app-store-submission.md) の 4 章と同じにする。Google Play の欄に合わせて、次のようにする。

| 項目 | 上限 | 案 |
|---|---|---|
| アプリ名 | 30文字 | ラテ帳：ラテアートの練習記録 |
| 簡単な説明 | 80文字 | 1杯ずつ動画と写真で記録して、ラテアートの上達が目で見える練習帳 |
| 詳しい説明 | 4000文字 | App Store の説明文（4-2）を使う。「■」は、そのまま使える |
| アプリのカテゴリ | － | ライフスタイル（タグは、フード／ドリンクなど） |
| アプリのアイコン | 512×512px | アプリのアイコン（透明なし） |
| フィーチャーグラフィック | 1024×500px | これから（アプリの画面とカップの写真で作る） |
| スマートフォンの画面写真 | 2〜8枚 | エミュレーターで撮る（スキル `app-screenshots`） |

上限の数字は、Play Console の画面で確認する。

## 6. データセーフティ（案）

プライバシーポリシー（`/privacy`）と食い違わないこと。**ログインした人の分だけ**、サーバーに置く。ログインしなければ、記録は、端末の外に出ない。

| データの種類（Play の分類） | 収集する？ | 用途 | 共有する？ |
|---|---|---|---|
| 個人情報 → ユーザー ID（Google のアカウント識別子） | する（ログインした人のみ） | アプリの機能（同期） | しない |
| 写真と動画 → 写真（縮小したもの）・動画（サムネイル） | する（ログインした人のみ） | アプリの機能（同期） | しない |
| アプリのアクティビティ → その他のユーザー作成コンテンツ（練習の記録・メモ） | する（ログインした人のみ） | アプリの機能（同期） | しない |
| メッセージ → その他のアプリ内メッセージ（「ご意見・ご要望」の本文・返信先） | する（送った人のみ） | アプリの機能・不具合の調査 | しない |
| アプリの情報とパフォーマンス → 診断（「ご意見・ご要望」に付く、OS・画面の種類・アプリの版） | する（送った人のみ） | 不具合の調査 | しない |
| 位置情報・連絡先・ファイル・健康・金融など | しない | － | － |

質問への答え：

- データは、転送中に暗号化されている：**はい**（HTTPS）
- ユーザーが、データの削除を依頼できる：**はい**（アプリ内：設定 → アカウント → アカウントを削除。ウェブのリンクは、2-2 で決めたもの）
- 動画の本体は、サーバーを通らず、端末から YouTube へ直接上がる（ユーザーが連携したときのみ）。YouTube の認可情報は、端末にだけ置く。

※ 分類の名前は、Play Console の画面の選択肢と照らして確定する。**「ご意見・ご要望」は、アプリにあとから足した機能なので、App Store の申告案（4-4）には入っていない。ポリシーには書いてある**ので、App Store 側の申告にも入れる必要がある。

## 7. そのほかの申告（案）

- **広告**：なし（広告も、アクセス解析のツールも使っていない）。
- **対象年齢**：子ども向けではない（13歳以上など、一般向け）。
- **コンテンツのレーティング**（質問票に答える）：暴力・性的表現・ギャンブル・ユーザー同士の共有などは、すべて「なし」。想定：全年齢。YouTube への動画のアップロードは、本人のチャンネルへ、本人が行う（SNS のような共有機能は無い）。
- **アプリのアクセス**（審査員がログインできるか）：ログインしなくても、すべての機能が使える。ログイン・YouTube の連携は、任意。
- **権限**：
  - カメラ：練習の様子と、できあがりを撮る
  - マイク：動画の音を録る（「音あり」を切ると使わない）
  - インターネット：ログイン・同期・YouTube への連携
  - 権限は、使うときに、許可を求める。許可されなくても、標準のカメラで撮れる。

## 8. 実機で確認してほしいこと（エミュレーターで確認できないもの）

エミュレーターで確認済み（Pixel 6・Android 16）：起動・各画面の表示・カメラの許可（許可する／しない）・録画（形式の切り替え）・写真・動画の編集（切り取り）・保存・再生・共有シート・バックアップの書き出し・戻るキー。

エミュレーターには、**H.264 のエンコーダーが無く、録画の挙動が実機と違う**（WebM になる）。次は、実機で確かめる。

1. **撮る → 編集 → 保存 → 共有 → アップ**：動画を撮り、「編集」で切り取り、保存し、「保存・共有」で他のアプリに渡せるか。録画は、まず MP4（H.264）を試し、作れない機種だけ WebM に切り替える作り。**実機では MP4 で撮れる**こと（共有されたファイルが `.mp4`。WebM になる機種があれば、機種名を控えて、アップまで通るかを確かめる）。
2. **YouTube へのアップロード**：設定 → 動画の保存先を YouTube にして、ログイン → 連携 → アップロード。
3. **Google ログインと同期**：ログイン → 別の端末（または iPhone）で、同じ記録が見えるか。
4. **戻るキー・ジェスチャー**：撮ったあとの入力画面で、端からのスワイプで戻る → 「保存せずに戻りますか？」が出るか。
5. **許可を断ったとき**：カメラ・マイクを断る → 「標準のカメラで撮る」で撮れるか。設定アプリで許可を戻すと、アプリのカメラで撮れるか。
6. **バックアップ**：書き出し → 「保存する」で、ドライブなどに保存できるか。復元できるか。
7. **機種の違い**：できれば、Pixel と、Pixel 以外（Samsung など）の2機種。

## 9. 提出後・ほかの注意

- **審査の時間**：新しいアプリは、数日〜1週間ほどかかることがある。公開済みの更新は、早いことが多い。
- **更新**：`versionCode` を +1 して、AAB を作り直し、上げる。App Store の更新と、バージョン名を揃えると、問い合わせのときに分かりやすい（iPhone：`1.0`）。
- **審査中のサーバー変更**：App Store・Google Play のどちらかが審査中のときは、サーバー（Worker）の変更をマージしない（方針）。

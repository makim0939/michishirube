## #102 の指摘

1. **版の更新（`package.json` を 1.0.0 に）を外す。** `docs/versioning.md` は「版を上げるのは、リリースの準備のとき。ふだんの PR では触らない」と書いている。版は、リリース用の PR で、`package.json`・iOS・Android の 3 つを、ビルド番号と一緒に上げる。`src/version.test.ts` は残してよい（ずれを検出するため）。
2. **次の版は 1.1.0 の想定。** 新機能・画面の変更はマイナー（docs の表）。今回の iPad 対応・タブ名の変更は、これに当たる。
3. **タグの方式を、文書に書く。** 文書は `v<版>`（例 `v1.1.0`）。1.0 は、審査に出したコミットに `v1.0-build2`（注釈付き、push 済み）を付けている。1.0 の審査に出したコミットは `package.json` が 0.2.0 なので、`v1.0.0` は付けない。
4. **Web 版の「お試し版です」の一行は、常設のまま（ユーザーの判断）。** Web 版は使い続けない想定で、アプリへの移行を促すため。閉じられる仕組みは要らない。ただし、リンク先（`apps.apple.com/app/id6823908010`）は、1.0 が公開されるまで開けない。このPRのマージは、**1.0 の公開後**にする。文言は、短く保つ。
5. **プライバシーポリシーの変更（問い合わせ先・最終更新日）は、Google の YouTube 審査の状況を確認してから。** 審査中のポリシーを変えると、審査が遅れる恐れがある。審査が終わっていなければ、マージを待つ（審査が終わっているか、ユーザーに確認すること）。
6. **「今週 N杯 · ラテ帳」の文言**（今日の画面のリンク）は、ユーザーの要望どおり。ただし、アプリ名とリンクの名前が同じで紛らわしいか、ユーザーに一言確認する。
